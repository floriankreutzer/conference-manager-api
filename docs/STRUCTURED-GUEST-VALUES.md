# Structured public Guest values (ADR-012 H-035)

Locations schema 3 adds nullable `guestPublicValues` to each Site and Room. `null` means no structured values are published. A Site object contains `publicTransport` and `parking` (`available` or `not_available`), `arrival` (`not_available`, `reception` or `organizer`), and up to four unique `accessibilityFeatures` (`step_free_entry`, `lift`, `accessible_toilet`, `hearing_loop`). A Room object contains `floorNumber` (null or integer -10 through 200) and the same accessibility feature set. Unknown keys, arbitrary text, duplicates and out-of-range values are rejected.

Tenant Admin owns Site values; Conference Manager owns Room values. The Locations aggregate revision, permissions, CSRF and audit remain authoritative. Schema 3 must be requested explicitly with `?schemaVersion=3` on reads and `schemaVersion: 3` on writes/rollbacks. Schema 1 and 2 remain exact and their writes preserve structured values. Migration 040 adds tenant-owned JSONB values and an immutable snapshot per Locations revision. It neither promotes old prose nor drops `guestInformation`, `floor`, or `accessibility`. Down migration refuses if current or historical structured values exist; use a forward fix in that case.

A confirmed Request's authenticated `room-context?projection=guest&schemaVersion=3` includes nullable Site `currentRoomContext.guestPublicValues` and Room `currentRoomContext.room.guestPublicValues`. The v2 Guest projection remains available only for an explicitly negotiated legacy client, but new UI displays and detached print use only the structured values for arrival, parking, public transport, floor and accessibility. Legacy free prose is withheld from this Guest projection. Site address/contact/route and Site/Room names are inherited separate public inputs with residual content risk; their review and product/security acceptance remain open. A null object displays missing information, and withdrawal takes effect on current Request context without rewriting old revisions.

Required release evidence: PostgreSQL migration/role/tenant/rollback checks, Chromium and WebKit Guest/editor/print states, exact cross-repository head pairing, deployed identity and named product acceptance. Passing repository CI alone does not close these gates.
