# Protected synthetic Customer handoff

This is inactive server-side custody, not protected INT activation or deployed
Microsoft/physical-device acceptance. Canonical migrations001..060 and Demo
001..026 remain unchanged. Additive061/027 are new reviewed-source candidates;
no live database migration, registration callback, secret or assurance default is
activated. The ordinary protected REAL email/Microsoft issuer stays invited-only.

The Customer root owns namespace-bound base sessions, the current deployment
shared lease, independent browser binding, stable source fingerprints and both
REAL/synthetic current-session readers. The unrestricted base issuer is private
and reachable only inside atomic consumed-handoff issuance. It is not exported to
routes. The anonymous start repository holds no Platform audit key or privileged approval
authority. The separate Platform aggregate owns approval; its application service uses
an actual private exact-operation passkey context and its future normal-MFA
continuation. Shared reset leases use a distinct bounded pool; nested Customer
cookie reads join the active business transaction, including max1 pools.

An anonymous start creates independent random state and original-browser nonce.
Only purpose/scope-bound MACs are durable. Starts are capped at5/source/minute and
30/environment/minute. Global retained slots1..5000 and per-owner approved slots
1..512 have database CHECK/UNIQUE constraints. Start allocation serializes the
bounded global budget; approval uses the existing owner-stamped exclusive RR
scope. Cleanup is bounded and preserves active session custody and24h consumed
history. Epoch rotation does not replenish stable source budgets.

Only the operator's own current synthetic generation is selectable, with fixed
Northwind/Contoso/Fabrikam slots and employee/conference_manager/tenant_admin
personas. Selection is a request, not authority: actual registry, lifecycle,
internal identity binding, stored roles and security versions determine access.
Employee is the implicit base for each persona. A Customer tenant_admin gains no
Platform role. No real Microsoft/email identity is bound to a synthetic User.

The fresh signed operation binds the environment, non-reusable UUID epoch,
Platform integer epoch, both fixed HTTPS origins, flow, state MAC, browser MAC,
actual owner, own generation, slot and role. Both actual credentials remain
required; none attestation cannot prove independent physical devices. The
mutation stores the newly issued normal-MFA session as source, never the old or
temporary elevated session. Proof, future session, audit and approval commit or
roll back together. A new independent random code exists only after proof; only
its MAC is stored. The private redirect result contains that code solely for the
fixed Customer callback. Lost redirects require a new start and new proof.
There is no approval polling/recovery endpoint or reusable elevated cookie.

Callback validation requires the original nonce, state and new code. It creates
only a signed completion lasting at most30s, bounded further by the60s code;
it never creates a Customer session. Confirmation reveals only the known slot,
role and bound CSRF. Final completion rechecks current source/owner/generation,
proof linkage, original browser, completion and CSRF, then atomically issues the
ordinary protected Customer session, appends canonical Tenant audit and consumes
the flow. The Customer session constraint is deferred so issuance and consumed
custody must exist at the same commit. Exactly one concurrent completion wins.

At final request time a REAL, unknown or foreign-owner cookie requires explicit
logout. A same-owner known synthetic session may be revoked and replaced, even
when the new proof has just revoked its former source MFA. Replacement custody
never grants business access. Locks follow operator/source, sorted Tenants,
sorted Users, previous session, then protocol row. A real login between callback
GET and final POST is preserved. This is a decision about the final request's
cookie, not a guarantee against arbitrary in-flight response races in a browser
cookie jar; a global browser-session-family mechanism is not introduced.

Every subsequent delegated request re-resolves the consumed flow, exact ordinary
session ID/identity/version/role/permission snapshot, current deployment, active
own generation, current source normal MFA, operator version and minimum two active
credentials. The historical proof must have been consumed before its own expiry;
that120s proof lifetime and60s code lifetime do not expire the ordinary8h Customer
session. Source expiry/revocation, recovery/version/key changes, generation/reset,
Tenant/User lifecycle or role changes deny subsequent delegated access.

All protected passkey instances must use the fixed retained-proof cleanup port,
including ordinary real-customer operations and login. A proof referenced by a
handoff cannot be deleted as expired challenge garbage. The production cap of5
unexpired challenges, including consumed challenges, remains unchanged. Old
binaries/legacy roots must be drained before activating this schema/profile.

Database trigger functions have fixed read-only SECURITY DEFINER contexts and
revoked PUBLIC execution; their shared approval invariant is SECURITY INVOKER,
void, trigger-context-only and private. No function returns a grant or accepts
arbitrary SQL. Populated custody/budgets/new audit prevent blind061 rollback;
active sessions and retained consumed history prevent deletion. Demo027 grants
only empty guarded TRUNCATE to the closed reset role, no read/DML/EXEC to either
Demo runtime. Closed Demo reset includes the empty new FK children. Protected
reset continues using the independent identity/history-preserving aggregate.

Transport composition remains separate work: narrow Secure/HttpOnly nonce and
completion cookies (Lax original callback, Strict completion), signed short Ops
intent preservation through login, URL scrubbing, same-origin mutation guards,
fixed303 redirect after the entire proof transaction commits, request limits and
privacy-safe route telemetry. No raw state/code/cookie/session IDs belong in
public JSON receipts, audit, logs, traces or browser storage. The new roots do not
install routes, start providers, send mail or enable a runtime profile.

Validation is recorded per exact source in the PR/CI, not inferred from this
file. Software P256 fixtures test actual verifier/database custody, not physical
key independence or live Microsoft authentication. A session surviving actual
proof expiry requires separately executed elapsed-time acceptance; unit clock
values and SQL predicates alone do not establish that evidence. The permanent
closed Demo three-customer progression and two-reset matrix remains required.
