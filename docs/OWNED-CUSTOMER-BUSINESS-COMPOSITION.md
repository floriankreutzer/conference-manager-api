# Owned Customer identity with canonical business composition

The Customer composition now accepts an explicit server-construction
`authenticationFactory` port. It is not configured from environment, browser,
header or query input. A future protected root must supply its actual owned
current-epoch invited/synthetic session composition; this port by itself grants
nothing and installs no protected root, route, provider, timer or migration.

The optional factory receives the existing fixed config, persistence and Tenant
audit service. Its closed synchronous result contains only `sessionService`.
Only five bound own function properties escape through the frozen HTTP session
port: current Principal resolution, CSRF verification/projection, revocation and
cookie clearing. Private issue/rotate methods remain with the owned admission
and handoff services. Missing, asynchronous, inherited/accessor or malformed ports
fail closed. A simultaneous generic Entra client is rejected; no fallback occurs.
Generic onboarding/JIT/OIDC services are never constructed in this path, and the
ordinary generic login/claim endpoints remain unavailable unless independently
installed by the owned root with the correct dedicated route modules.

The default null factory preserves existing generic Customer construction. That
unchanged session/onboarding/JIT/OIDC assembly is extracted into one composition
module rather than duplicated. Canonical request, booking, room, media, settings,
User, audit, entitlement and Microsoft business services remain in the same
Customer composition and receive the selected HTTP session port. Route factories
and server composition see that same object. Startup, shutdown, readiness,
provider requirements and disabled job behavior remain unchanged. Actual trusted
roots must still fix provider mode, current reset fences, persistence credentials
and no-generic-admission activation; this port is no acceptance of those controls.

The architecture gate treats the new module as composition: domain, application,
HTTP, persistence and provider modules cannot depend on it. Existing Demo graphs
still reject its transitive generic identity dependencies. Tests use ordinary
PostgreSQL persistence construction pointing only to an unused loopback port,
with forbidden provider operations and throw-on-access generic session/JIT/OIDC
repositories. No database or provider connection is opened. They verify canonical
business services still construct, both consumers receive the same minimized
session port and generic admission remains null. Negative shape/provider/async
and architecture tests supplement existing generic Customer/job regression.
No native or whole-root evidence is claimed by these construction tests.
