# Protected real Customer onboarding

This prepared repository wrapper is uncomposed. It creates no live Tenant,
recipient, email, credential, migration or deployment. Exact-source native and
whole protected runtime acceptance remain mandatory under SaaS1 issue351.

The owned factory reuses ordinary Platform-authorized customer onboarding,
configured owner-inclusive invitations, encrypted custody, operation receipts and
both audit domains. It fixes environment and protected UUID epoch at server
composition. There is no browser-selected classification mode.

Creation requires the exact enclosing live shared deployment lease for its own
business pool, environment and UUID epoch. That lease stays on the separate
bounded pool while the ordinary exact-proof RR transaction uses the business
pool. Its read-only marker survives the nested business transaction, rejects
foreign/detached scopes and grants no authentication, proof or permission.

Ordinary Platform target-policy reads now join the existing proof transaction
through the canonical transaction adapter when no explicit client is supplied.
They retain its RR snapshot and current operator/version/scope predicates instead
of requesting another connection from an already pinned max1 business pool.
Outside a proof they own an ordinary transaction; explicit-client calls keep
their existing contract. No target, role or permission decision is broadened.

The wrapper locks/rechecks the current deployment inside the same business
transaction. After ordinary creation succeeds it inserts immutable REAL registry
custody, then verifies that exact environment/Tenant classification. The registry,
Tenant, invitations, mailbox custody, queued deliveries, both audits and receipt
therefore commit together with the proof. A registry failure rolls back the
complete creation; a later classification cannot expose a latent earlier grant.

Idempotent replay must already have its original exact REAL classification. An
older unclassified receipt is rejected and never retroactively registered; a
synthetic or foreign-environment target cannot be relabelled. User identity,
Customer session, external Microsoft directory and outbound email delivery remain
separate contracts. Protected mode-qualified email eligibility/worker composition
is still required before sending any queued message.

Focused tests cover server scope validation, missing enclosing lease, current
deployment readback before mutation, nested RR marker identity and released/
foreign marker denial. The native extension requires actual PostgreSQL and pinned
WebAuthn software-key proof with max1 pools: owner-inclusive invitation creation,
atomic classification, idempotent replay, injected registry failure rollback,
unclassified historical receipt rejection and environment/epoch denial. It is
not local PostgreSQL, physical-key, live-provider or protected-root acceptance.
